# 장대장 계산기 익명 이용 통계 보는 법 (GA4)

회원가입 없이 쓰는 서비스라 **개인을 알아볼 수 없는 구간 값만** 모읍니다. 광고·제휴 영업 자료에는
"어느 지역(시군구)에서, 어떤 예산대의 사람이, 얼마나 관심을 보이는가"를 이 통계로 보여 줍니다.

- 보내는 코드: `assets/stat.js` 의 `jdjStat(이벤트, 값)` (GA4 측정 ID 상수도 이 파일 맨 위 한 곳)
- 페이지 기본 방문·유입 채널: `assets/track.js` (기존)
- 보내지 않는 것: 이름, 전화, 주소·지번, 단지명·건물명, 정확한 소득·현금·예산·가격, 생년월일 등 날짜, 자유 입력 글,
  세금 계산 입력값(세금 계산기는 '사용했다'는 사실만)
- 허용 목록에 없는 이벤트·값, 형식이 맞지 않는 값은 `stat.js` 가 전송 전에 버립니다. 같은 값은 한 페이지에서 한 번만 보냅니다.
- 주소창의 계산 조건(연소득 `i`, 현금 `c`, 이름 `n` 등)은 GA로 가지 않도록 `track.js` 가 페이지 주소를 정리해서 보냅니다.

## 1. 보내는 이벤트

| 이벤트 | 언제 | 값(맞춤 측정기준) |
|---|---|---|
| `feature_use` | 기능을 실제로 썼을 때 (페이지당 기능별 1회) | `feature`: buy 내 집 마련 · report 리포트 · switch 갈아타기 · redev 재개발(정비구역 확인) · villa 빌라 · chungyak 청약 · tax 세금 · compare 단지 비교 · consult 상담 신청 버튼 · premium 프리미엄 리포트(상품 선택·결제 화면·결제 완료·리포트 열람, 금액·연락처·주문번호는 보내지 않음) / `from`: 상담 신청이 눌린 페이지 |
| `interest_profile` | 결과를 본 뒤(입력이 멈춘 뒤) | `sido` 시·도 · `sgg` 시군구 · `budget_band` 예산대(1억 단위) · `hold_band` 예상 보유 기간 · `home_own` 주택 보유 · `region_group` 규제 구분 · `from` 어느 기능에서 |
| `chungyak_result` | 청약 가점 계산 결과를 봤을 때 | `score_band` 가점 10점 구간 · `home_own` 무주택/유주택 |
| `report_share` | 리포트 공유 버튼 | `method`: share(휴대폰 공유) / copy(주소 복사) |
| `compare_use` | 단지 비교 화면을 봤을 때 | `n` 비교한 단지 수 |
| `ad_view` | '분양 광고' 칸에 광고가 보였을 때 | `slot` 노출 위치(bunyang·villa …) · `n` 보인 광고 수 |
| `ad_click` | 분양 광고의 '공고·홈페이지 보기'를 눌렀을 때 | `slot` 노출 위치 · `ad_kind` 주택 유형 · `sido` 시·도 (광고 id·단지명은 보내지 않음) |

모든 이벤트에 `page`(보낸 페이지)가 붙습니다.

구간 값 예시
- `budget_band`: 1억 미만, 1~2억, 2~3억 … 29~30억, 30억 이상 (내 집 마련·리포트·갈아타기 = 살 수 있는 최대 금액, 단지 비교 = 비교한 단지의 시세 구간)
- `hold_band`: 2년 이하, 3~5년, 6~9년, 10년 이상
- `home_own`: 무주택, 생애최초, 1주택, 다주택, 유주택(청약)
- `score_band`: 0~9점, 10~19점 … 70~79점, 80~84점

월 방문자·재방문율은 GA4 기본 지표(사용자, 신규 사용자, 재방문자)로 봅니다. 따로 보내는 값은 없습니다.

## 2. 처음 한 번만 하는 설정 (GA4 관리)

맞춤 측정기준은 **등록한 날부터** 쌓입니다(과거 소급 안 됨). 가장 먼저 해 두세요.

1. GA4 → 관리(톱니바퀴) → 데이터 표시 → **맞춤 정의** → 맞춤 측정기준 만들기.
   범위는 모두 **이벤트**, '이벤트 매개변수'에 아래 이름을 그대로 넣습니다.

   | 측정기준 이름(보기 좋게) | 이벤트 매개변수 |
   |---|---|
   | 기능 | `feature` |
   | 보낸 페이지 | `page` |
   | 유입 기능 | `from` |
   | 시도 | `sido` |
   | 시군구 | `sgg` |
   | 예산대 | `budget_band` |
   | 예상 보유 기간 | `hold_band` |
   | 주택 보유 | `home_own` |
   | 규제 구분 | `region_group` |
   | 청약 가점 구간 | `score_band` |
   | 공유 방식 | `method` |
   | 유입 채널(기존) | `channel` |

   (선택) 맞춤 측정항목: 비교 단지 수 = `n`, 단위 '표준'.
2. 관리 → 데이터 수집 및 수정 → **데이터 보관** → 이벤트 데이터 보관 **14개월** (탐색 보고서로 1년 추이를 보려면 필요).
3. 관리 → 데이터 스트림 → 웹 스트림 → **향상된 측정** 톱니바퀴에서
   - **이탈 클릭**: 끄기 (상담 신청 링크에 자동 입력된 신청서 내용이 링크 주소째 기록되는 것을 막음. 상담 클릭은 `feature_use`=consult 로 따로 셉니다)
   - **페이지 변경(브라우저 기록 이벤트 기반)**: 끄기 (리포트가 주소를 바꿀 때 계산 조건이 담긴 주소가 기록되는 것을 막음)
4. 같은 웹 스트림 → **데이터 수정(Redact data)** → URL 쿼리 매개변수 수정 켜고 다음 이름을 넣기(이중 안전장치):
   `i, c, d, n, e, o, t, rt, tm, r, sd, g, hz` 와 상담 신청서 칸 `entry.146176170, entry.1872979900, entry.397234060, entry.1054811896, entry.658364183`
   (개수 제한에 걸리면 `i, c, n, d, e` 와 `entry.*` 다섯 개를 먼저)
5. 관리 → 데이터 수집 → **Google 신호 데이터**: 끄기 권장 (켜 두면 적은 인원 행이 '기준점 적용'으로 숨겨지고, 익명 집계 원칙에도 맞지 않음).

## 3. 보고서 만드는 순서 (탐색 → 자유 형식)

GA4 → 탐색 → **자유 형식** 새로 만들기. 왼쪽 '변수'에서 측정기준·측정항목을 + 로 가져옵니다.
기간은 오른쪽 위에서 지정(예: 지난달 1일~말일).

### A. 월 방문자·재방문율
- 측정기준: `월`, `신규/재방문`  · 측정항목: `활성 사용자`, `신규 사용자`, `세션`
- 행: 월 / 열: 신규/재방문 / 값: 활성 사용자
- 재방문율 = 재방문(returning) 활성 사용자 ÷ 전체 활성 사용자
- 유입 채널별로 보려면 측정기준 `유입 채널`(channel, 이벤트 범위) 또는 기본 `세션 소스/매체` 를 행에 추가

### B. 기능별 사용 수
- 측정기준: `이벤트 이름`, `기능` · 측정항목: `이벤트 수`, `활성 사용자`
- 필터: 이벤트 이름 = `feature_use`
- 행: 기능 / 값: 활성 사용자(몇 명이 썼나), 이벤트 수(몇 번 썼나)
- 상담 신청이 어느 기능에서 나왔는지: 필터에 기능 = consult 추가, 행을 `유입 기능` 으로

### C. 관심 지역 × 예산대 (영업 자료 핵심 표)
- 측정기준: `이벤트 이름`, `시도`, `시군구`, `예산대`, `예상 보유 기간`, `주택 보유`, `유입 기능`
- 측정항목: **활성 사용자** (같은 사람이 조건을 여러 번 바꿔도 한 명으로 셈 — 영업 자료에는 이 숫자를 쓰세요)
- 필터: 이벤트 이름 = `interest_profile`
- 행: 시도 → 시군구 (행 '중첩' 켜기) / 열: 예산대 / 값: 활성 사용자
- 보유 기간·주택 보유 비율: 열을 `예상 보유 기간` 또는 `주택 보유` 로 바꿔 같은 표를 다시 보기
- 시각화를 '히트맵'(셀 서식 → 히트맵)으로 바꾸면 "강남구 15~16억 무주택 몇 명" 같은 표가 바로 나옵니다
- 참고: `sgg` 가 비어 있는 행은 시군구를 고르지 않았거나(내 집 마련에서 '전체') 리포트에서 6곳 이상 고른 경우입니다

### D. 청약 가점 구간 분포
- 측정기준: `청약 가점 구간`, `주택 보유` · 측정항목: 활성 사용자
- 필터: 이벤트 이름 = `chungyak_result`
- 시각화: 막대 그래프. 행 = 청약 가점 구간

### E. 리포트 공유 수
- 필터: 이벤트 이름 = `report_share` · 행: `공유 방식` · 값: 이벤트 수, 활성 사용자

탐색 보고서는 오른쪽 위 '공유'로 다른 계정과 함께 보거나, 내보내기(Google Sheets·CSV·PDF)로 영업 자료에 붙입니다.

## 4. 영업 자료로 쓸 때 주의

- **활성 사용자 기준 숫자**를 쓰고, "이 브라우저 기준 익명 집계(같은 사람이 다른 기기에서 쓰면 따로 셈)"라고 적어 주세요.
- 한 칸의 인원이 아주 적으면(예: 10명 미만) 시군구를 시도로 묶거나 예산대를 3억 단위로 묶어 보여 주세요.
- 광고 차단기·추적 방지 브라우저 사용자는 집계되지 않아 실제보다 적게 나옵니다(보수적인 숫자).

## 5. 새 페이지에 넣는 법 (예: 세금 계산기 `tax/`)

```html
<script>window.JDJ_CONFIG = { tool:'tax', GA4_ID:'(stat.js와 같은 ID)', CLARITY_ID:'' };</script>
<script src="../assets/track.js"></script>
<script src="../assets/stat.js"></script>
```

계산 결과를 보여 주는 함수 끝에 **사용 여부만** 보냅니다(입력값은 절대 넣지 않음).

```js
if (window.jdjStat) jdjStat('feature_use', {feature:'tax'});
```

새 값 이름이 필요하면 `stat.js` 의 허용 목록(`P`)과 이벤트 목록(`EV`)에 구간 형식으로 먼저 추가하고, 위 2-1의 맞춤 측정기준에도 등록하세요.
`JDJ_DEBUG = true` 를 브라우저 콘솔에 넣으면 보내는 값과 버린 값이 콘솔에 찍힙니다.
