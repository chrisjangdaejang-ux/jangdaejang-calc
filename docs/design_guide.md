# 집예보 화면 배치 가이드 (PC · 휴대폰)

목표: 들어오자마자 **결론 한 줄과 핵심 숫자**가 눈에 들어오고, 자세한 내용은 원할 때 펼쳐 보게 한다.
흰 바탕·남색 집·열쇠 구멍 로고·쉬운 우리말은 그대로. 2026-11-26 대표 승인 개편안(시안)부터 아래 '0. 색'과 '13~16' 규칙을 함께 따른다.

공용 파일
- `assets/layout.css` — 토큰(글자·간격·폭)과 공용 배치 규칙
- `assets/layout.js` — PC 오른쪽 요약 칸·목차, 휴대폰 긴 칸 접기, 결과로 바로 내려가기, 핵심 숫자 먼저
- `assets/tabbar.js` — 휴대폰은 아래 탭, PC는 머리줄 가로 메뉴
- 페이지마다 따로 고치지 말고 위 파일의 규칙·속성으로 맞춘다. 고치면 `?v=` 를 올린다.

## 2. 폭과 두 칸 배치(PC)

- 전체 최대 폭 `--w-page` 1160px, 글 읽기 칸 `--w-read` 760px.
- **본문 + 오른쪽 요약 칸**(1200px 이상): `<body data-lay="side">`
  - 오른쪽 300px 칸이 화면을 따라 내려온다(sticky).
  - 위: 핵심 숫자(`data-lay-key=".stats"` 로 고른 칸을 그대로 복사 — 숫자를 새로 만들지 않음)
  - 아래: 이 화면 목차(보이는 h2, `data-lay-toc` 로 바꿀 수 있음). 지금 보는 칸은 파랑.
  - 목차가 2개 미만이고 숫자도 없으면 칸을 만들지 않고 원래 폭으로 둔다.
  - 단지 비교처럼 가로 폭 자체가 중요한 화면은 쓰지 않는다.
- **홈**: 위 = 소개 글(왼쪽) + 바로 가기 버튼(오른쪽) / 가운데 = 오늘 소식·우리 지역 지금(왼쪽) + 브리핑·물어보기(오른쪽, 따라 내려옴) / 서비스 메뉴 4칸 / 아래 링크 2칸.
- 휴대폰에서는 묶음이 없는 것처럼 원래 순서 그대로 세로로 쌓인다(순서를 바꾸지 않는다).

## 3. 지도(PC 나눠 보기)

- 1024px 이상: 왼쪽 400px 목록 + 오른쪽 지도. 위쪽 검색·필터 줄은 그대로.
- 목록 = 지금 지도에 보이는 곳(시·도·구·동·단지). 지도에 올린 말풍선과 **같은 값**만 보여 준다.
- 지도를 움직이면 목록도 바뀐다. 줄을 누르면 말풍선을 누른 것과 같다.
- 순서: 거래 많은 순 / (단지일 때) 값 높은 순 / 가나다 순.
- 단지 카드는 떠 있는 작은 창 대신 목록 자리에 붙여 연다(닫으면 목록으로).
- 지역 분석 칸이 열리면 그 칸이 목록 자리를 쓴다.
- 휴대폰: 지도 전체 + 아래에서 올라오는 카드(지금 방식 유지).

| `--fs-sm` | 13.5px | 보조 설명 |
| `--fs-md` | 15px | 칩·작은 버튼 |
| `--fs-body` | 16px | 본문 |
| `--fs-lg` | 18px | 카드 제목 |
| `--fs-xl` | 20px | 칸 제목(h2) |

- 간격은 4의 배수만: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40.
- 카드 안 여백 휴대폰 16~20px, PC 20~24px. 카드 사이 12~16px, 큰 묶음 사이 24~32px.
- 줄 간격 본문 1.6, 숫자 칸 1.3.

## 5. 카드·칸 짜임: 결론 한 줄 → 핵심 숫자 → 접는 자세히

1. **결론 한 줄**: 이 화면에서 가장 중요한 문장(예: "1년 전보다 8.7% 올랐고…").
2. **핵심 숫자 칸** 2~4개: 맨 앞 칸 = 사람들이 가장 궁금한 숫자 한 개(파랑 바탕). 숫자 아래에 기준(기간·면적).
3. **자세히**: 계산 근거·표·긴 목록은 접어 둔다(`details` 또는 휴대폰 `data-lay-fold`).
- 휴대폰에서 900px보다 긴 칸은 `data-lay-fold="선택자"` 로 560px만 보이고 '펼쳐 보기'. 안에 있는 입력 칸에 손이 가면 저절로 펼친다.
- 결과 링크로 들어온 휴대폰은 `data-lay-jump="#res"` 로 결과 첫 칸으로 한 번 내려 준다(이미 스크롤했으면 안 함).
- 핵심 숫자가 긴 설명 뒤에 있으면 `data-lay-keyfirst` 로 보이는 순서만 앞으로(내용은 그대로).

## 6. 차트

- 폭은 칸 폭 100%. 높이: 휴대폰 220~260px, PC 280~320px(가격 추이), 막대·거래량 160~200px.
- 맨 위에 "가장 최근 값" 한 줄을 늘 보여 주고, 누르거나 손가락을 대면 그 달 값으로 바뀐다(공용 차트).
- 가로축 날짜는 4~6개만. 세로축은 억/만 단위로 짧게.
- 범례는 차트 바로 아래 한 줄. 색만으로 구분하지 않고 선 모양(점선)도 함께.

## 7. 칩·필터 줄

- 공용 칩 줄 도우미 `assets/chiprow.js` 를 쓴다: 칩 줄 요소에 `data-chiprow="평형 더보기"` 만 붙이면 된다(나중에 그려도 됨).
- 휴대폰(768px 미만): 한 줄 가로 밀기 + 오른쪽 흐림 + '›' 버튼 + '…더보기'(누르면 모두 펼침). 줄바꿈으로 3줄 이상 쌓지 않는다.
- PC(768px 이상): 줄바꿈해서 모두 보이게(가로 스크롤 없음).
- 칩 높이 44px(작은 화면 안 보조 칩은 36px까지), 고른 칩은 파랑 테두리 + 연파랑 바탕.
- 필터는 왼쪽 세로 막대가 아니라 위쪽 가로 줄에 둔다.

## 8. 메뉴 (대표 결정 2026-11-26)

- 휴대폰: 아래 탭 5개 **홈 · 고민 찾기 · 지도 · 내 집 · 전체**, 높이 58px + 안전 영역(`assets/tabbar.js`).
  - 고민 찾기: 고민 해결 길잡이(`GUIDE_ENABLED`)가 켜지면 `solve/`, 꺼진 동안은 첫 화면 맨 위 찾기 칸(`./#q`, 단지·기능 찾기 — `assets/ask.js`).
  - 내 집: `mine/`. 전체: `all/`(순위·단지 비교·지역별 실거래가 등은 여기와 첫 화면 '상황별로 찾기'에서 들어간다. 순위·단지 비교 화면에서는 '전체'가 켜진 탭).
  - 길잡이 대화창(`solve/?chat=1`)에서는 탭을 숨긴다(`body.gchat-on`).
- PC(1024px+): 같은 5개를 머리줄 로고 오른쪽 가로 메뉴로. 1024~1279px은 글자만, 1280px+는 그림+글자.
- 5개를 넘기지 않는다.

## 9. 누르기·글자 대비

- 누르는 칸은 가로·세로 44px 이상(`--tap`). 주요 버튼 48~56px.
- 글자 대비 4.5:1 이상. 회색 글자는 `--sub2`(#4E5968)보다 흐리게 쓰지 않는다. PC는 보조 글자를 한 단계 진하게.
- 색만으로 뜻을 전하지 않는다(오름/내림은 +/− 기호도 함께).

## 10. 숫자 쓰기

- 집값: `29억 2,200만원`, 짧게는 `29.2억`. 1억 미만은 `9,850만원`. 0 은 빼고 `30억원`.
- 평당가: `평당 4,292만`(전용 3.3㎡당이라고 한 번은 밝힌다).
- 변동률: `+0.8%` / `−5.2%`, 오름은 빨강(`--up`)·내림은 파랑(`--down`) + ▲▼ 또는 +/− 기호. ±0.5% 안은 회색 '거의 같음'.
- 건수 `7건`, 단지 `1,693곳`, 세대 `9,510세대`. 천 단위 쉼표, 표 안 숫자는 고정폭 숫자(`.num`).
- 날짜 `2026.10`, 기간 `2026.08~2026.10`. 기준일을 숫자 가까이에 둔다.
- 자료에 없는 숫자는 만들지 않는다. 값이 없으면 '자료 없음'·'최근 거래 없음'.

## 11. 빈 화면·불러오는 중

- 불러오는 중: 칸 높이를 미리 잡고 "자료를 불러오고 있어요…" 한 줄(화면이 밀리지 않게).
- 빈 결과: 왜 비었는지 + 다음에 할 일 한 줄(예: "이 화면에는 표시할 단지가 없어요. 지도를 움직이거나 확대해 보세요.").
- 오류: "잠시 뒤 다시 열어 주세요." 숫자 0 으로 채우지 않는다.

## 13. 첫 화면 (대표 승인 시안 2026-11-26)

위에서부터: **"무엇이 고민이세요?"**(h1 하나, 위에 대표 문구 "집값도, 할 일도 미리 알려 드려요") → 찾기 칸 → 상황 단추 9개(집 사려고요·이사 갈 집·전세·월세·청약·분양·세금·대출·재개발·빌라·상가·건물·전체 기능 — 3칸 × 3줄, 휴대폰·PC 같은 배치, 전체 기능은 늘 마지막. 새 단추는 3의 배수로 맞추거나 전체 기능 화면에만 둔다) → 상단 광고 → **내 집 · 할 일**(관심 목록·먼저 챙겨 드려요·전세 만기 알림) → 모닝 브리핑 카드 → 오늘의 집값 소식 → 우리 지역 지금 → **상황별로 찾기**(시세·지도 / 집을 사기 전 / 팔고 옮길 때 / 전세·월세, 4묶음) → 이렇게 계산해요(소개 글) → 공유·상담·중개사.
- 길잡이가 켜지면 찾기 칸·상황 단추 자리를 길잡이 칸(`#guideTop`)이 대신한다(`.qh.g-on`).
- '이사 갈 집' 단추는 `assets/switch-pick.js` 가 [집이 있어요]·[전월세 살아요]를 그 아래 한 줄 전체로 펼친다.
- PC: 위 = 왼쪽 질문·상황 단추 / 오른쪽 광고·내 집·할 일·브리핑, 가운데 = 오늘 소식·우리 지역(왼쪽) + 정확도·이렇게 계산해요(오른쪽, 따라 내려옴), 아래 = 상황별로 찾기 4칸.
- 진한 남색 꽉 찬 단추는 한 화면 묶음에 1개(찾기 단추·브리핑 받기).

## 14. 전체 기능 (`all/`)

- 상황별 8묶음(시세·지도 / 집을 사기 전 / 전세·월세 / 팔고 옮길 때 / 청약·분양 / 재개발·빌라·상가 / 매일 챙겨 보기 / 도움 받기), 줄마다 아이콘 + 이름 + 한 줄 설명.

## 15. 결과 화면 공통 틀

모든 계산기 결과는 같은 순서: **결론 한 줄(큰 숫자) → 핵심 숫자 2~4칸 → 왜 그런가요(근거) → 조심할 점 → 출처(접기) → 이어서 하면 좋은 것 3개**(`assets/guide-next.js` 공통 부품).
- 결론 카드는 먹색 바탕 한 장(결과 맨 위), 큰 숫자 휴대폰 40px / PC 52px. 미래가치 점수는 '예보 막대'(평균보다 덜 오를 쪽 ↔ 더 오를 쪽 5칸)로.
- 계산 숫자는 화면이 이미 계산한 값을 그대로 옮긴다(새로 계산하지 않음).
- 공용 파일: `assets/result.css`(겉모양) + `assets/result.js`(`JDJ_RF.fc` 예보 막대 · `JDJ_RF.lean` 점수 한 줄 · `JDJ_RF.trend` '1년 전보다 …% 올랐어요'). 페이지 `<style>` 뒤에 읽는다.
  - 결론 카드 `class="rf-v"`(예전 `.result` 에 붙여도 됨 — `.lbl`·`.big`·`.why`·`.sub`·`.binding` 그대로 먹색 카드로), 카드 안에 숫자 칸·근거가 함께 그려지는 화면(세금)은 `rf-v rf-in`.
  - 핵심 숫자 줄 `class="rf-keys"`(휴대폰 2칸, 768px+ 칸 수만큼 한 줄), 조심할 점 칸 `rf-warn`(첫 h2 앞에 ! 표시), 출처·계산 근거 `<details class="rf-src">`, 다음 단계 링크 묶음 `rf-next`(첫 링크가 가장 권하는 것, 테두리 남색).
  - 길잡이 해법 카드(`.gcard`)와 '이어서 하면 좋은 것'(`assets/guide-next.js` `.gnx`)도 같은 모양을 따른다(길잡이 파일은 고치지 않음).
- 적용 화면: 내 집 시세(mine) · 대출(loan) · 내 집 마련(buy) · 세금(tax 5가지) · 청약(chungyak) · 갈아타기(switch) · 전세 갈아타기(switch/rent) · 전월세(jeonse) · 길잡이(solve).
- 계산 코드가 쓰는 요소 id 는 바꾸지 않는다. 바꾼 뒤에는 같은 입력으로 결과 숫자가 바꾸기 전과 모두 같은지 대조한다(결과 칸 글자 속 숫자 모음 비교).

## 16. 배지·NEW

- 배지는 한 화면 묶음에 1개까지. 보기용 숫자·문장에는 '예시' 배지.
- 'NEW'·'새로'는 출시 날짜를 적고(`data-new="2026-11-26"`) 14일이 지나면 자동으로 사라진다(`assets/tabbar.js` 의 `JDJ_NEW` — 하단 탭이 있는 모든 화면, 나중에 그리는 배지는 `JDJ_NEW.fresh(날짜)` 로 판단).

## 17. 글자 크기 단계

큰 숫자 40/52 · 첫 화면 제목 30/40 · 화면 제목 26/32 · 묶음 제목 21 · 카드 제목 18 · 본문 16 · 보조 14 · 작은 글씨 12.5px(이보다 작게 쓰지 않음). 앞 숫자는 휴대폰/PC.
- 화면 `<style>` 에는 색 값을 직접 쓰지 않고 aplus.css 토큰(`var(--blue)`·`--blue-d`·`--blue-l`·`--text`·`--sub`·`--sub2`·`--gray`·`--gray2`·`--line`·`--line2`·`--up`·`--down`·`--pos`·`--neg`·`--gold`)을 쓴다(2026-11-26 3차에서 45개 화면 739곳 교체). 생성 페이지(apt/·cy/·comm/)는 직접 고치지 않고 `assets/seo.css` 로만 따라간다.

## 18. 단추 무게

- 진한 꽉 찬 단추(남색·먹색)는 한 화면 묶음에 1개 — 그 묶음에서 가장 하고 싶은 일(계산하기·저장·찾기·추천받기).
- 공유하기·결과 공유·전문가 상담 신청·지도에서 보기·바깥 사이트 바로 가기 같은 보조 동작은 흰 바탕 + 연남색 테두리(`aplus.css` 마지막 규칙이 공통으로 맞춤).
- 하단 탭(`assets/tabbar.js`)은 관리자·중개사 도구·결제 진행·인쇄용 리포트를 뺀 모든 화면에 둔다. 인쇄할 때는 숨긴다.
